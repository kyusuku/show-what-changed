## Implemented behavior

Motion records actual CDP PNG frames with app animations enabled. Fixed Date leaves animation clocks running. Every raw PNG passes bounded structural, decompression, dimension, and CRC checks before decode. Fixed rectangles are filled and verified as opaque #101010 before persistence. Motion checkpoints use the same sanitizer. Keyframes retain selector masks and animation-disabled screenshots.

Each side has one fixed source-clock mapping. Calibration uses bracketed Performance metrics, then later samples validate the same offset. Source markers retain their measured source value and host bracket. Missing clocks, source regression, incompatible metadata, or a combined bound above 40 ms fail the side. A failed clock retains its original mapping and observed excessive bound.

Actions use strict exact locators, including inner scroll targets. Smooth scrolling verifies its clamped destination and settlement. Step timeouts cover lookup, action, fonts, animation frames, observation, and checkpoint. Required failures block later side actions. Allowed zero-match absence and exclusions remain unverified pairs. A fault after one side finishes while its peer is pending changes that side's actual result rather than leaving a false success.

The raw queue remains at most two frames per side with a 128 MiB shared conservative raw-buffer budget. Raw strings and decoded buffers are released before acknowledgement or persistence backpressure. Sanitized PNG persistence is ordered and bounded separately. Its hard caps are 256 safe PNGs per side and 32 MiB shared across the run. ACK backpressure begins at 128 safe PNGs per side or 16 MiB shared. It resumes on actual persistence progress. Fault, abort, and cleanup deadline wake blocked acknowledgements. Storage still has the incremental 12000-PNG and 10-GiB limits, including checkpoints.

Only successful durable writes create serialized motion-frame records. Observed receipt, persistence, acknowledgement, and rejection counters remain separate. Browser-produced drops are unknown, represented by null. Source gaps are observations. They do not assert a dropped-frame count. A write failure prevents later queued writes. Cancellation and a drain deadline account for an already completed safe write and discard later queued work. Stop drains before bundle return. Successful scenario duration ends at the actual source-stop/final-step boundary, excluding a later durability drain. Failed/blocked markers remain inside their observed scenario interval.

Composition uses actual latest-eligible source selections on a common 30-FPS schedule. The saved timeline binds the canonical capture digest, exact scenario and step boundaries, annotations, source artifacts, poster identity, and all image hashes. `validateTimelineCapture` is exported and encode independently loads and validates capture.json. Source substitutions and retiming fail even when a malicious timeline remains internally self-consistent.

Trusted static HTML renders titles, labels, captions, status overlays, and posters. Source panels in motion overlays are verified transparent. A single bounded RGBA pipe supplies FFmpeg split, crop, no-upscale scale, pad, stack, and overlay filters. No browser renders every output frame. Capability checking exercises those filters. Encoding validates H.264, yuv420p, CFR 30, count, dimensions, duration, and decoded first, boundary, and final images. Offline recovery uses saved media inputs without a browser, font, application runtime, or server.
