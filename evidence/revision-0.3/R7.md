## App and recipe contracts

The recipe uses schema 2 and selects `apps/web` explicitly. Both setup commands run with `cwd: "."` at repository root. Startup defaults to the selected app directory and runs `node server.mjs {port}`. The server source binds `127.0.0.1` and its assigned port. The readiness path is the normal `/board` route. The only declared generated directory is the new shared build output. The app uses no external services or persisted data. No service has been replaced or intercepted.

The navigation scenario has 11 steps. It opens the board, opens and closes the actual library drawer, scrolls its inner list, and follows the client link to the proposal route. The drawer and backdrop use 320 ms CSS transitions. The list's own scroll handler reads its `scrollTop` and updates a visible footer and bound attributes. Its assertion requires `[data-testid="library-scroll-readout"][data-scrolled="true"]`. Its shared checkpoint is `library-inner-scroll`.

The validation scenario has nine steps. It navigates from the board, fills the synthetic invalid values `x` and `broken`, submits to the normal form API, waits for the actual alert, and records the shared `validation-feedback` checkpoint. Both scenarios use only shared steps with no missing-side exclusions.
