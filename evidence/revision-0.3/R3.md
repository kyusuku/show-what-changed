# R3 runtime evidence

R3 implements the schema 2 execution lifecycle for general web applications. The runtime returns `RuntimeResult` with server identities, private validated auth state, and safe per-side execution provenance.

The implementation preserves the existing detached process anchors and PID/start-time checks. Application environment maps extend the tool allowlist explicitly. Parent environment references resolve once and services receive their own maps. Literal values, template source values, and every resolved consumer-specific environment value enter both the private public-text registry and the child-process sensitive-value list before use. Prerequisites use the application PATH and record selected executable paths and observed versions privately.

Private helper copies retain exact bytes, filename extensions, and executable-bit semantics. Both sides receive independent state directories and ports. Ordered service setup/start precedes application setup/start, HTTP readiness, bootstrap, and authentication-state validation. Container consumers receive internal ports and aliases. Host consumers receive published loopback endpoints.

The Docker adapter binds a selected local Unix endpoint and a private client configuration. The configuration contains resolved buildx plugin directories and no copied authentication, credential-helper, or context configuration. Intended names and ownership labels are saved before create/build operations. Private ledger version 2 records pending creation names before daemon-side create, builder bootstrap, or image build/load. A 404 cannot settle a pending operation. Only an inspected owned identity clears the intent. Legacy version 1 records with missing identities remain uncertain. Recovery continues removing confirmed owned resources when another intent is unresolved, and failed physical cleanup retains the repository lock. Builders have unpredictable registered node, container, and state-volume names. Container, network, and final-image cleanup verifies exact IDs and labels. Container image VOLUME declarations become bounded tmpfs mounts after protected-path checks. Inspected mounts, network IDs, loopback mappings, image IDs, and liveness must match the declared resources.

Cleanup stops capture acceptance before contexts and browsers, then stops owned process groups, builders, containers, networks, and owned images. It disposes private execution directories and workspaces after successful ownership checks. Cleanup has a separate 30-second budget. Its buildx commands use a separate supervised command lane and process ledger. Exact daemon inspection/removal uses bounded Unix-socket requests. Image deletion sets `noprune=1` and does not force deletion. The [Docker Engine API reference](https://docs.docker.com/reference/api/engine/version/v1.53/) documents the exact inspection and deletion operations.
