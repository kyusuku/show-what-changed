# R2. General source snapshots and pure planning

Implemented against the schema 2 module contracts. This evidence covers the current working tree. Final candidate identity, cross-platform acceptance, and release certification remain integration work.

## Behavior

- Planning requires an explicit general execution recipe. It runs no application or helper commands. Static, Python, npm, and pnpm workspace inputs are accepted without package-manager source gates.
- Inventories cover the complete repository. Tracked static assets, build directories, dependency paths, shared packages, and nested directories with tool-like names remain inputs. Only root Git internals and registered tool outputs are omitted.
- Git trees contain metadata only. Blob payloads are consumed sequentially in chunks of at most 64 KiB. Disk hashing and snapshot overlay copying use bounded reads through checked regular-file descriptors. The reader checks identity, size, mode, mtime, and ctime after reading.
- Source budgets default to 1 GiB and 100,000 paths. Explicit settings allow 2 GiB and 200,000 paths. A separate 512 MiB single-file bound applies. Plans contain measured file counts, byte counts, fingerprints, and complete frozen inventories.
- Snapshot preparation creates independent complete Git worktrees and performs no dependency installation. It validates copied bytes and executable modes, rechecks the caller and destination, and retains source settings for subsequent verification.
- Generated-directory declarations cannot cover eligible existing inputs at either endpoint or in the caller. Only later eligible files within validated declarations can be omitted. A new source file elsewhere invalidates provenance.
- Explicit scenarios and routes precede automatic discovery. Automatic App Router discovery is scoped to appDir and retains conservative shared-change, dynamic-route, slot, interception, and omission reporting. Markdown content, API handlers, and private shared components remain unresolved when their route impact is unknown.
- Plans bind raw config/scenario documents, normalized config/scenarios, and declared helper paths, hashes, sizes, executable flags, and extensions. Helper paths resolve relative to the config directory and respect the 16-file/8-MiB aggregate cap. Runtime consumes only those declared bindings.
- Saved plans pin exact commits. WORKTREE plans additionally require the pinned HEAD and final filesystem inventory. Ref names moving later do not retarget explicit-ref plans. Plan persistence and reads accept up to 128 MiB; config and scenario documents remain bounded at 1 MiB.

## Source identity repair after independent review

The independent review reproduced two P1 failures. Root `.show-what-changed` application files were omitted by name, and Git replacement refs could substitute bytes beneath a recorded original commit OID. This repair keeps general application source eligible and makes managed Git read the selected objects directly.

All managed Git calls now use `--no-replace-objects`. The shared child environment also sets `GIT_GRAFT_FILE=/dev/null`. A separate real-graph regression showed that disabling replacement objects alone did not disable legacy graft ancestry. Ref resolution, merge-base, tree and diff inspection, streaming blob reads, worktree creation, reset, and later verification share these controls. Caller replacement refs and graft-file bytes remain intact.

Source discovery retains every HEAD-tracked and index-tracked path, including tracked files under verified output roots. Untracked discovery excludes only a matching plan/owner hash pair, run roots validated by the existing run-owner parser, and a run-lock owner file matching its validated run marker. Git receives anchored exclusions before untracked traversal. A private temporary exclusion file avoids argument-length limits and is removed after enumeration. Arbitrary files and unregistered run directories under the root output prefix remain eligible inputs and count against budgets. Invalid committed entry types at that prefix receive the ordinary unsupported-source diagnostic.

Snapshot re-inventory receives an explicit empty output registry. Application-written ownership records cannot hide new snapshot files. A declared generated application directory under the output prefix follows the ordinary generated-directory contract. It must contain no eligible existing inputs, and only later generated files are excluded.

Fixed plan and run paths are checked against tracked source before writes. Orphan or invalid plan records block replacement before a plan-write lock is created. Root files, symlinks, and unsafe output ancestors fail without overwriting caller bytes. Fresh run directories still use exclusive creation. Plan replacement binds both existing file hashes and rechecks each target immediately before replacement. The plan-write lock is bound to its filesystem identity and removed only while owned and empty. A real filesystem race reproduced the previous cleanup deleting a replacement lock containing application files; that behavior is repaired.

Late hash and lock checks are best-effort filesystem race detection. They do not provide compare-and-swap or an atomic two-file transaction. The durable regression cases inject a concurrent edit at the real file-sync boundary, then perform real hash checks, writes, and cleanup. This avoids dependence on coalesced directory-watch notifications. The original source-identity reproducer uses actual Git worktrees without timing injection.
