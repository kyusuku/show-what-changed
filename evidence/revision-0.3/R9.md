## Outputs and cleanup

`motion-check.json` reports one case per completed attempt. Each case has `result.json` and, after a numeric pass, copied synthetic `compare.mp4`, `poster.png`, `capture.json`, and `timeline.json`. The report binds copied artifacts and saved case results to actual hashes and bytes. The owned `.show-what-changed` run beneath each case retains safe source frames, overlays, and private diagnostics. The copied capture and timeline retain their original run-relative paths. Use the complete retained run for offline recomposition.

Each pipeline has a 240-second run deadline. The full-video decode is an installed-supervisor child with a 120-second deadline and two decoder threads. It writes no more than the timeline's declared frame count. Fixture servers bind only loopback. SIGINT and SIGTERM abort through the run controller. Every case closes its own servers and executes installed runtime cleanup in `finally`. Success requires an `ok` cleanup outcome, absent owned process groups, absent repository lock, absent temporary workspaces, and closed fixture listeners. Failures retain their case and aggregate reports where process survival permits. No unrelated process or file is removed.

Exit 0 means the requested numeric checks passed. Exit 1 means a pipeline, numeric, interruption, or cleanup check failed. Exit 2 means invalid invocation or setup before a report could be created. Numeric success always leaves `visualReview.status` as `pending` and `releaseAcceptance` as `not-evaluated`. Review every copied video at normal speed and record perceptual quality separately. The verifier does not assert overall web-app compatibility, Linux or macOS acceptance, source provenance, or owner publishing readiness from this synthetic check.
