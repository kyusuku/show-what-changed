# N1 source isolation and runtime ownership

N1 supplies the workspace and runtime layer for the v0.1 release candidate. This is a module integration handoff, not a release-readiness claim.

## Plan and checkpoint

The source model is a byte-sorted inventory of present regular files and explicit absent entries. The lifecycle model is a live child handle, process-group ownership and exact owned filesystem identities. Shared persisted contracts remain unchanged.

1. Implement `src/runtime/{files,context,supervisor,browser}.ts` and expose the frozen helper APIs. Verify private atomic writes, symlink rejection, cancellation and cleanup with real child processes.
2. Implement `src/workspace/{git,source,index}.ts`. Inspect both Git endpoints without executing repository code. Materialize separate detached worktrees, overlay final filesystem bytes, independently install and verify source identities.
3. Implement `src/runtime/{index,ownership}.ts`. Verify listener process groups and loopback bindings before readiness. Add safe diagnosis and exact owned cleanup helpers.
4. Add focused real Git/process tests in `test/unit/{source,snapshot,runtime}.test.ts` and `test/integration/lifecycle.test.ts`. Run strict typecheck and the focused Vitest gates. Record commands, outcomes and gaps.

The throughput checkpoint was completed. Runtime file/context/browser helpers were delivered to N2/N3 before source inspection was delivered to N4. Subsequent integration additions were `renameRunFile`, `reopenRunContext`, streaming artifact hashes and cancellation-aware source inspection.

## Implementation

- `workspace/git.ts` uses argument arrays, disables hooks/fsmonitor/external diff, rejects malformed refs and paths, reads exact Git trees without conversion, and measures source bytes before loading blobs.
- `workspace/source.ts` implements full endpoint preflight, unique merge-base resolution, exact no-renames commit diff, and the union of HEAD/index/nonignored filesystem candidates for WORKTREE. It checks package/lock compatibility, source limits, filters/attributes, modes, LFS, local/private dependencies and unsupported layouts.
- `workspace/index.ts` creates separate detached worktrees without checkout, checks each linked worktree's effective Git configuration, then materializes. WORKTREE copying verifies both original and destination inventories. Independent `npm ci --no-audit --no-fund` installs are followed by full source checks on both sides. `verify` also detects newly added eligible files after capture.
- `runtime/supervisor.ts` owns every spawned command through a live process-group anchor. Actual server exit is reported immediately. Probe/install/encode output is drained before their exit result settles, and their timeout remains active through draining. Group cleanup uses the live anchor or verified live members and never an unverified persisted PID.
- `runtime/index.ts` allocates distinct loopback ports, checks every listener with lsof/ps, requires exact status and origin, rejects fallback/nonloopback/unrelated servers, and limits conflict retries to two additional pairs.
- `runtime/context.ts`, `ownership.ts` and `files.ts` provide private contained output, atomic writes, streaming artifact hashing, locks, resume, diagnosis and exact owned cleanup. Cleanup closes contexts/browsers before process groups, removes registered workspaces and then releases the lock. Failures preserve the lock and surface a failed cleanup outcome.
- `runtime/browser.ts` uses sandboxed Playwright launchServer/connect and immediately adopts the live BrowserServer child. Normal close and an actual Chromium crash were tested.

Type System Discipline kept public boundaries on the existing schema-derived contracts. Model the Domain kept source existence, registered resources and live process ownership explicit instead of inferring them from filenames or persisted PIDs.

## Independent review and repairs

The independent review is recorded in `evidence/N1-independent-review.md`.

1. A short-lived leader could spawn a child after the initial process inventory and exit before polling. Cleanup could no longer prove the group's identity. The repair adds the live tool-owned group anchor. The original real orphan probe and regression now pass with an empty group and unrelated processes alive.
2. Conditional Git includes activated only inside a linked worktree could introduce filters after caller preflight. The repair creates with `--no-checkout`, preflights the effective linked-worktree configuration and attributes, verifies its registered root, then materializes. The original smudge sentinel remains absent.
3. Follow-up probes checked inherited stdio. Separate command-exit and stream-close messages preserve immediate server liveness and complete probe output. The command timeout remains active while output is draining. All independent follow-up probes passed.

## Integration and remaining gates

No N1 implementation stub remains. The integrator owns the terminal result/manifest reducer and CLI signal mapping. Full CLI success/partial/cancel checks at every phase, packed-package tests and Linux execution remain N5 through N9 gates. This host's evidence must not be presented as Linux evidence.

Execution consent remains essential. The tool is not a security sandbox. Deliberately detached daemon processes can leave the supervised group, and trusted app scripts can access the user's account and network. Unknown or changed ownership is refused instead of guessed. Filesystem snapshot consistency is best-effort detection of concurrent edits; it is not a filesystem-wide transaction.

No commits, publication, upload or other public mutation were performed by the N1 owner. Requesting root integration and final review.
